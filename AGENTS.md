# AGENTS.md

Asia-session opening-range breakout backtester for M1 gold (XAUUSD). FastAPI dashboard over a pure-Python backtest engine. All logic is UTC-only.

## Setup & run

```bash
python3 run.py    # one-command launcher: creates .venv, installs deps, honors PORT env (default 8000)
python3 -m venv .venv && source .venv/bin/activate   # deps are NOT installed on the system python
pip install -r requirements.txt                       # fastapi, uvicorn[standard], pandas, numpy, python-multipart, jinja2
python3 -m uvicorn app.main:app --host 0.0.0.0 --port 8000   # MUST run from repo root (imports are app.engine.*)
```

UI at `http://localhost:8000`. No test suite, no pytest, no lint/typecheck config exists.

## Architecture

- `app/engine/` is framework-agnostic and importable standalone (notebook/script): `data_loader` (CSV -> UTC DataFrame) -> `session` (daily windows, trading days) -> `strategy` (breakout detection, entry modes, SL/TP) -> `backtester` (per-day loop, exit simulation) -> `stats` (summary, trade log, equity curve) -> `montecarlo` (post-process resampling of R-multiples).
- `app/defaults.py` is the SINGLE source of truth for every tunable default value (strategy params, upload defaults, capital-sim and Monte Carlo defaults). `strategy.Params`, `main.BacktestParams`, `CapitalSimParams`, `MonteCarloParams`, the export endpoint, and the `index.html` template (server-rendered `value=`/`checked=` plus an injected `window.DEFAULTS` JSON the JS reads) all draw from it. Never hardcode a default elsewhere; bounds/validation constraints stay with their models.
- `app/main.py` is a thin transport layer: routes call the engine, then keep results in module-level in-memory dicts (`DATA_STORE`, `RESULT_STORE`). Everything is lost on restart; this is a single-user local tool.
- README's "Verified behavior" section is the strategy spec; the engine docstrings are the closest thing to an authoritative description of intended behavior. Reconcile behavior changes against them.
- Frontend is vanilla JS + a hand-rolled canvas equity chart (no chart library).

## Invariants (easy to break, deliberately implemented)

- Timestamps are tz-aware UTC end-to-end. Uploads take a `source_tz`; the loader NEVER guesses silently. `"auto"` (UI default) infers the offset from weekend gaps (Sunday reopen 22:00 UTC anchor + Friday close ~21:00 UTC check, broker range -5..+5h) and raises a clear error instead of guessing when the data has no reliable signal (`detect_utc_offset`). Uploads can include MULTIPLE files (mixed formats OK): each is loaded independently via `load_ohlcv_csv` (a failure in any file aborts with the file's name in the error), then merged via `merge_loaded` (concat, sort, dedupe `timestamp` keeping FIRST occurrence). The upload response includes `files: [{source, rows, start, end, tz_note}]` plus merged totals.
- CSV schema: `timestamp, open, high, low, close` (+optional `volume`). Aliases (date/time or date/hour/minute split columns, o/h/l/c) are merged; headerless MetaTrader-style exports (`date time, o, h, l, c, v`) are auto-detected via the first cell parsing as a datetime. Mixed timestamp formats are tolerated: ISO-8601 rows (`2025-11-17T14:02:00Z`, e.g. an appended export block) are normalized to `YYYY-MM-DD HH:MM:SS` before parsing, because pandas 3.x NaTs the minority format in a mixed column; the stripped `Z` merely labels UTC, which `source_tz`/`"auto"` still resolve. Rows where high/low don't bound open/close are REJECTED on upload.
- `POST /api/data/upload` takes `files` (multipart, repeated for multiple files) plus `symbol`/`source_tz` form fields. Per-file failures abort with `"<filename>: <detail>"` as the 400 detail.
- `Params.pip_size = 0.01` hardcoded (gold convention); `spread_pips`/`slippage_pips` are in pips and applied adversely on entry and exit.
- `session_open_utc` is an "HH:MM" string applied per calendar day. Trading days are selected by ISO weekday (`trading_days`, Mon=0..Fri=4): the UI offers "all weekdays" or a custom Mon-Fri subset, and Sat/Sun are never traded. The API validates a non-empty subset of 0-6; the engine's `get_trading_days` filters by `dayofweek.isin(trading_days)`.
- `/api/backtest/run` accepts optional `start_date`/`end_date` (DD/MM/YYYY or ISO, inclusive days UTC) that window the dataset before the backtest; `_normalize_date` in main.py is the single parser. The endpoint streams the run as NDJSON: one `{"type":"progress","done","total"}` line per trading day (fed by the engine's `progress_cb` from a daemon thread), then a final `{"type":"done","result":{...}}` or `{"type":"error","detail"}` line.
- At most ONE trade per day structurally (single opening range per day); no max-trades parameter exists.
- Market entry fills at the NEXT bar's open after the breakout candle (never the breakout close). Limit entry fills at the broken boundary only if touched before `search_deadline`, else expires.
- SL is anchored at range midpoint: `sl_pct_of_range 0.5` = exact midpoint, `1.0` = opposite boundary. TP = `tp_rr` x risk distance from entry. `sl_ladder` (default `((0.5, -0.5),)`, empty tuple = no moves) is a list of `(trigger_R, sl_R_from_entry)` steps, R = the ORIGINAL risk distance (entry to initial SL), fixed for the whole trade — a moved stop never re-anchors later steps (initial SL is -1.0R, so negative levels are between entry and the initial stop, 0 = breakeven, positive = locked profit). When a candle touches a step's trigger, the SL moves to that step's level from the NEXT candle on (trigger bar is evaluated against the old stop; conservative). Steps are auto-sorted by trigger (order of entry never matters): a bar racing across several triggers applies the highest reached step's stop directly. TP is checked before stop-moves, so a bar reaching TP in one candle exits at TP and no ladder step fires. Trades record `sl_moved` and `sl_final` (the last stop in force at exit, always numeric). Validation (after sorting) requires trigger > 0, stops >= -1.0, stops non-decreasing, and stop < its own trigger.
- Same-bar SL+TP touch resolves to SL (conservative, no tick data). Timeout exits at the last close at/before entry + `session_max_hours`; with no future bars it exits at entry price, 0R.
- Days with no trade are recorded in `result.no_trade_days` with a reason (`no_range_data` | `no_breakout` | `no_fill`) — do not drop this.
- Capital simulation is a PURE POST-PROCESS over trade R-multiples — it never touches the backtest engine or re-runs. `simulate_capital(trades, initial_capital, risk_pct, compounding)` in stats.py: fixed mode risks `initial × p` dollars per trade; compounding applies `equity_{n-1} × (1 + r_n × p)`. Simulation order is exit-time sort; `CapitalSim.pnl` must be aligned to the INPUT trade list order (the API's result trades are already exit-time sorted, so the two coincide — verify if that ever changes). `POST /api/backtest/simulate/{job_id}` validates `initial_capital > 0`, `0 < risk_pct < 10`, `mode in {fixed, compounding}` and 404s on unknown job. `GET /api/backtest/export/{job_id}` accepts `capital` (0/1 flag), `initial_capital`, `risk_pct`, `mode` query params; `pnl_usd` column only when `capital=1`. The UI re-simulates on any Capital tab change (debounced 400ms, `refreshSim`); renderers take the sim payload (R-only when disabled — never pass null into number formatting, use `lastResult` fallback).
- Monte Carlo is ALSO a pure post-process over trade R-multiples (`run_monte_carlo` in montecarlo.py) — never touches or re-runs the engine. It resamples the observed `r_multiple`s — `shuffle` = order permutation (sum of R preserved, so under fixed sizing the final return is invariant; the drawdown spread is the useful output), `bootstrap` = draw with replacement (the final-return spread quantifies edge robustness) — then runs each path through the SAME fixed/compounding sizing math as `simulate_capital`. Deterministic via `np.random.default_rng(seed)` (seed None = random). `POST /api/backtest/montecarlo/{job_id}` validates `1 <= iterations <= 10000`, `sample_mode in {shuffle, bootstrap, both}`, `seed >= 0 | None`, `initial_capital > 0`, `0 < risk_pct < 10`, `sizing in {fixed, compounding}`, `target_pct > 0`, `max_dd_pct > 0`; 404s on unknown job, 400 on zero trades. Response: `params`, `n_trades`, `variants` keyed by the modes actually run — each a MonteCarloVariant with `actual_*` (the realized path, stopped the same way: the realized account pauses at its own first boundary, so `actual_final_return_pct` is exactly `+target_pct` when the realized run passed), `*_percentiles` (5/25/50/75/95 — `final_return_*` (snapped to the boundaries), `max_drawdown_*`, and `trades_stop_*` of how many trades accounts ran before pausing), `p_loss`, a per-trade `trades_histogram` `[[center (trades), passed, blown, neither], ...]` (one bin per trading day) of how many trades each account took before its first event, split by outcome, and account-level outcomes where `total_accounts == iterations` (the number of accounts tested). Each account is a prop-firm CHALLENGE and STOPS at the FIRST event: `passed_accounts` = reached the target return before breaching the DD limit (its final return is exactly `+target_pct` — the challenge pays the target, not more), `blown_accounts` = breached the DD limit before reaching target (its final return is exactly `-max_dd_pct` — the account is halted at its max loss), so `passed + blown <= total` (the remainder ran all trades without hitting either event and keep their actual end value); `pass_rate` = passed / total, `risk_of_ruin` = blown / total. No account can show a final return past its own boundary — the "+75% kept running" outcomes are impossible by design. `avg_trades_to_target` / `avg_trades_to_blow` are the mean trade count at the first event among accounts that passed / blew (null when none did, which the JS renders as "—"). MC has its own capital/risk/target/dd parameters (independent of the Capital tab); frontend state `lastMc` drives the Monte Carlo results panel + histogram canvases, enabled only when a job exists. The UI is split into two global pages (`#mainTabs` toggles `.gpage` elements): `backtest` = the params sidebar (Data/Strategy/Risk/Capital tabs) + results, `montecarlo` = MC params sidebar + `#mcEmptyState` / `#mcPanel`. `renderMc()` keeps `#mcEmptyState` and `#mcPanel` mutually exclusive; it is called by `runMonteCarlo` and whenever a job is cleared or re-generated (`handleClear`/`handleGenerate` set `lastMc = null` and call it).

- Frontend state: `lastResult` (backtest payload) and `lastSim` (simulate payload, null when capital disabled) are the single source for all rendering via `renderAll()`. `renderEquityCurve(curveR, curve$, initialCap)` draws ONE curve only (app.js:802 `const curve = curve$ || curveR`) — $ as the primary axis when a sim is present, cumulative R otherwise; there is deliberately no R overlay, and the tooltip shows date + $ + P&L + % in USD mode or date + R in R mode. Trade table P&L column and breakdown `$` totals index `sim.pnl` by the SAME index as `lastResult.trades` (both exit-time order).
